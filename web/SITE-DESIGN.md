# サイト設計メモ

このファイルは web/ の情報設計、レイアウト、文言の方針を定めます。実装より先に決め、実装後もここに合わせて直します。

## 誰が何のために見るか

| 読者 | 来る理由 | 最初の 30 秒で欲しいもの |
|---|---|---|
| 非エンジニア（PM、デザイナー、経営） | AwesomeDS が何かを知りたい。良いデザインの根拠を確認したい | 見た目の実物と、短い理由 |
| エンジニア | 自分のプロダクトに入れたい | インストール手順、トークン、コンポーネントのコード |
| AI エージェントを使う人 | プラグインの使い方を知りたい | スキル一覧と 1 行の使い方 |

判断: トップは「実物 → 理由 → 入れ方」の順にする。説明文より先に、AwesomeDS で作ったフォームの実物を置く。

## 情報設計

```
/                      はじめに（実物、要点、入れ方）
/foundations/typography 文字
/foundations/color      色
/foundations/spacing    余白とレイアウト
/foundations/radius     角丸
/foundations/elevation  奥行き
/foundations/motion     モーション
/components             コンポーネント（1 ページ、アンカー）
/animation              アニメーションライブラリ（1 ページ、アンカー）

/knowledge/:cat/:slug   ナレッジ本文

```

サイドバー（lg 以上で常時表示、それ未満はシート）:

- はじめに
- 基盤: 文字 / 色 / 余白とレイアウト / 角丸 / 奥行き / モーション
- コンポーネント
- アニメーション
- ナレッジ（カテゴリ別）
- 出典
- このサイトについて

## レイアウト

- トップバー 64px。左にワードマーク「AwesomeDS」と mono の「v0.1.0」。右にテーマ切替（ライト / ダーク / OS）と GitHub リンク。ナビはサイドバーに寄せ、トップバーには置かない（1 行に収まらないリスクを消す）。
- 本文カラム: 文章は 65ch（約 720px）、プレビューは最大 1040px まで広げる。
- 見出し: ページに h1 は 1 つ。セクションは h2。eyebrow ラベルは使わない。
- 余白: セクション間 64px（モバイル 48px）。プレビューと説明文の間 24px。
- 配置: すべて左揃え。中央揃えは空状態の 1 行だけ。
- 背景: canvas のみ。装飾のグラデーション、ブロブ、ガラスは使わない。

## ページの型（基盤ページ）

1. **結論**: ルールを 1〜2 行。直下にトークンのコード（コピー可）。
2. **実物**: 生きた見本。ライト / ダーク切替、必要なら幅切替（390 / 1024）。
3. **なぜ**: 3〜5 項目。各項目は 1〜2 文と出典リンク 1 つ。
4. **良い例と避ける例**: 左右に並べた 1 組。避ける例には理由を 1 行。
5. **出典**: このページで引いたリンクの一覧。

## プレビュー枠（Preview）

- 上部にタブ: プレビュー / コード。
- 右上に小さなツール: ライト / ダーク、幅（デスクトップ / モバイル）。
- 枠は hairline 1px、角丸 12、背景は canvas。内側パディング 24。
- コードは Geist Mono 13px、コピー用ボタン付き。実際のソースを `?raw` で読む。

## コンポーネントページ

各コンポーネントは同じ骨格: 名前、1 行のルール、Preview、状態一覧（hover / focus / active / disabled / loading）、使うトークン、やらないこと。

順序: Button, Input, Textarea, Select, Checkbox, Radio, Switch, Card, Dialog, Popover, Tooltip, Tabs, Table, Toast, Badge, Avatar, Skeleton, Empty, Error, Navigation。

## アニメーションページ

各ライブラリは同じ骨格: いつ使うか（1 行）、使わないとき（1 行）、Preview、コード、公式リンク。

順序: CSS transition（基準）, Motion, GSAP ScrollTrigger, Lottie, three.js（react-three-fiber）, CSS scroll-driven animation。

reduced-motion のトグルを用意し、切ると各デモがどう振る舞うかを見せる。

## ナレッジページ

- 一覧: 検索欄 1 つ、カテゴリのタブ、カードではなく行のリスト（タイトル、種別、更新日、タグ）。
- 本文: 先頭に出典リンクのリスト、次に Markdown 本文。末尾に「AwesomeDS への反映」が来る。

## 文言の規則

- 動詞で終える。名詞の羅列にしない。
- 1 文 40 字前後。長いなら分ける。
- 「洗練された」「美しい」「シームレス」「体験を向上」などの評価語は使わない。事実と数値で言う。
- 比喩を使わない。em ダッシュ（—）を使わない。「〜することができます」は「〜できます」。
- 英語の固有名詞とトークン名はそのまま。
- 各ページの最初の文は「何であるか」を言う。感想から始めない。

## トップページの文言（案）

h1: AwesomeDS
lead: ブランドをまだ持たないプロダクトが、そのまま使えるデザインシステムです。白地に黒文字、アクセント 1 色、Geist と Noto Sans JP、4px の余白単位。値にはすべて理由と出典があります。

実物の見出し: 実物
実物の説明: 下のフォームは、このサイトと同じトークンだけで作られています。ライトとダークを切り替えて、余白、角丸、フォーカスリング、ボタンの状態を確かめてください。

要点（3 つ）:
- 文字: Geist と Noto Sans JP。本文 16px、行間 1.6（日本語 1.8）。
- 色: 白地 #ffffff、黒 #0a0a0a、アクセント #2f5bea はリンクとフォーカスと選択にだけ使う。
- 余白と形: 4px 単位。角丸は操作部品 8、カード 12、ダイアログ 16。

入れ方の見出し: 使い方
1. Claude Code に入れる: /plugin marketplace add Yu-aimaker/Awesome-Design-Systems-Claude
2. 直接使う: DESIGN.md をプロジェクトに置き、tokens.css を読み込む。

## 避けること（このサイト自身）

- 3 枚並びの同じカード。
- 中央揃えのヒーロー。
- 見出し上の小さな大文字ラベル。
- 装飾のためのアニメーション。動くのはユーザー操作の応答と初回表示の 200ms だけ。
- 「AI」や「モダン」を売り文句にする文。
